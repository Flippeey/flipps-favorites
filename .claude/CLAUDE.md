# Project: Flipp's Favorites

A browser extension that replaces the new tab page with a bookmark dashboard. Targets Chrome (Manifest V3) and Firefox (MV3, Firefox 140+). No frontend framework — vanilla TypeScript + DOM + CSS.

## Tech Stack

- **Language**: TypeScript (strict mode, ES2022 target)
- **Build**: Vite (`vite.config.mjs`) — single source, dual output
- **Extension spec**: Manifest V3 for both Chrome and Firefox
- **No framework**: Vanilla DOM manipulation, no React/Vue/etc.
- **No test framework**: Type checking via `npm run typecheck` is primary validation
- **CSS**: Plain CSS modules imported via `src/newtab/styles/index.css`

## Build Commands

```bash
npm run build          # Build both Chrome and Firefox
npm run build:chrome   # Output to dist/chrome/
npm run build:firefox  # Output to dist/firefox/
npm run typecheck      # Type-check without emitting
npm run dev            # Vite dev server
```

Manifest files are generated by `scripts/write-manifest.mjs` as a post-build step. Environment variables control version, description, Firefox extension ID, update URL, and whether HTTP hosts are included.

## Architecture

### Two Entry Points

1. **`src/background/service-worker.ts`** — Extension background. Handles install/update lifecycle, routes all UI↔Background messages, manages icon resolution.
2. **`newtab.html` + `src/newtab/main.ts`** — New tab page UI. Full application bootstrap, state management, event handling, and rendering.

### Module Structure

```
src/
├── background/
│   ├── service-worker.ts       # Lifecycle + message router
│   └── icons/icon-service.ts  # Icon resolution pipeline
├── newtab/
│   ├── main.ts                 # App entry, state, event loop
│   ├── state/                  # AppState type, derived state, transitions, selection
│   ├── bookmarks/              # Dialog, navigation, ops, usage tracking
│   ├── helpers/                # Open/validate/navigate/persist utilities
│   ├── icons/                  # Runtime hydration + CSS rendering
│   ├── interaction/            # Drag-drop, context menus, click handlers
│   ├── onboarding/             # Multi-step onboarding wizard
│   ├── ui/                     # Context menus, status overlays
│   └── styles/                 # CSS split into 10 focused files
├── settings/
│   ├── config/options.ts       # Settings schema and UI option lists
│   └── ui/render.ts            # Settings drawer rendering
└── shared/
    ├── messages.ts             # ALL message types + shared data models (source of truth)
    ├── browser.ts              # Chrome/Firefox API compatibility shim
    ├── storage.ts              # Storage bucket management
    ├── storage-buckets.ts      # Generic CachedValueStore / CachedRecordStore
    ├── html-escape.ts          # XSS prevention
    └── ui-icons.ts             # SVG icon helpers
```

### Key Design Patterns

**Message-first communication**: The newtab UI never calls browser APIs directly. All operations (bookmarks, settings, icons) go through typed messages defined in `src/shared/messages.ts`. The service worker handles them and responds.

**Centralized state**: `AppState` in `src/newtab/state/app-state.ts` is the single source of truth for the newtab UI. It includes undo/redo stacks, clipboard, selection, dialog state, icon cache, onboarding status, and more. State mutations go through helpers in `state-transitions.ts`.

**Storage abstraction**: `CachedValueStore` and `CachedRecordStore` in `shared/storage-buckets.ts` wrap the browser storage API with lazy loading and change listeners. Settings prefer sync storage with local fallback.

**Icon pipeline**: Override → in-memory cache → Google S2 favicons → DuckDuckGo image search. Request deduplication prevents concurrent fetches for the same URL.

**Dual-target build**: Same TypeScript source compiles to both Chrome and Firefox. Browser compatibility is handled by `shared/browser.ts` which exports `extensionApi` (resolves to `browser` or `chrome` global).

**Folder navigation**: Hash-based (`#folderId`). "Remember last folder" option persists across sessions. Breadcrumbs are derived from the bookmark tree.

## Conventions and Approach

- **No framework**: Add DOM manipulation inline or via small focused helper functions. Do not introduce React, Vue, or similar.
- **Strict TypeScript**: All code must type-check cleanly. Run `npm run typecheck` to verify.
- **Shared types first**: When adding a new feature that crosses the background/newtab boundary, define message types in `shared/messages.ts` before implementing either side.
- **XSS safety**: User-supplied strings must go through `shared/html-escape.ts` before being set as `innerHTML`. Use `textContent` where possible.
- **CSS naming**: Styles are split into focused CSS files under `src/newtab/styles/`. Add styles to the most relevant existing file; only create a new file if clearly warranted.
- **Build both targets**: Changes should work for both Chrome and Firefox. Use `extensionApi` from `shared/browser.ts` instead of `chrome.*` directly.
- **No tests currently**: Validate logic changes by running the build and type-checking. Do not add a test framework without discussion.
- **Permissions**: Avoid requesting new manifest permissions unless strictly necessary. The extension is intentionally least-privilege.
