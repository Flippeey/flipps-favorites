# Flipp's Favorites — Claude Reference

Browser extension. New tab page = bookmark dashboard. Chrome MV3 + Firefox MV3 (140+).
React 19 SPA in newtab; vanilla TS service worker.

## Rules

- Keep working files and tests in `tests/` or `docs/` — not the repo root.
- After every code change, run `npm run build` — typecheck runs automatically via hook. Both Chrome and Firefox builds must pass.
- Cross-context calls go through the message pipeline (`shared/messages.ts` → `lib/messaging.ts` → `service-worker.ts`). Use `extensionApi` from `shared/browser.ts` for any browser API — never raw `chrome.*` / `browser.*`.
- Strict TS: `unknown` + narrowing at boundaries, never `any`. Treat React state as immutable (`{ ...prev }` / `new Set(prev.ids)`).
- Prefer JSX text children for rendering (React escapes). Avoid `innerHTML`.

## Tech Stack

- TypeScript 5.8 (strict, ES2022, `moduleResolution: Bundler`). `@/*` path alias → `src/*` (tsconfig + vite); prefer it over deep relative imports.
- React 19 + ReactDOM 19 — functional components + hooks only.
- Vite 6 + `@vitejs/plugin-react` 5 — dual output via `--mode chrome` / `--mode firefox`. Manifest V3 both targets.
- Tests: Playwright 1.58 (`tests/specs/*.spec.ts`) + Vitest 3 (`tests/unit/**/*.test.ts`).
- Plain CSS, no preprocessor. Import chain (order matters): `styles/index.css` → `tokens`, `base`, `nav`, `hero`, `tiles`, `overlay`, `dock`, `dialogs`, `settings-drawer`, `onboarding`, `interactions`, `responsive`.
- npm, `type: module`. Runtime deps: `react`, `react-dom` only. Discuss before adding any new top-level dependency, state library, or CSS framework.

## Layout (src/)

- `background/service-worker.ts` — MV3 message router + lifecycle. `background/icons/` — icon resolution pipeline (entry: `icon-service.ts`).
- `newtab/App.tsx` — owns top-level state; composes hooks from `newtab/state/` (`useSelection`, `useWorkspaceActions`, `useToasts`, `useContextMenuBuilder`, `useOptimisticPatch`). Child components are presentational (props + `on*` callbacks).
- `newtab/components/` — React components; `components/settings/` holds per-section drawer panels (Appearance, Layout, Clock, Dock, Navigation, Backup, Help). `TemplatePicker.tsx` — onboarding template selector.
- `newtab/lib/tree-profile.ts`, `archetype-match.ts` — archetype classification pipeline (structural profiling + 3-class matcher).
- `shared/organization-templates.ts` — per-archetype view/sort template bundles.
- `newtab/interaction/` — pointer/keyboard hooks (`useDrag`/`useDragWiring`, `useMarquee`, `useKeyboardNav`, `useFocusTrap`, `useQuickAddShortcuts`, `useWorkspaceShortcut`, `useEscapeKey`).
- `newtab/lib/` — utilities (`messaging`, `tree`, `url`, `accent`, `dock-mode`, `folder-scoring`, icon helpers, `platform`, `workspace-transfer`).
- `shared/` — cross-context code (`messages` = source of truth for contracts, `models`, `browser` shim, `storage` + `storage-buckets`, `icon-idb`, `constants`).

## Commands

```bash
npm run build            # Both targets → dist/{chrome,firefox}
npm run build:chrome     # / build:firefox — single target
npm run typecheck        # tsc --noEmit
npm run test:unit        # Vitest unit tests (fast, no browser)
npm test                 # Playwright chrome project — needs a fresh `npm run build` first (global-setup only checks dist exists, it does NOT build)
npm run test:firefox     # Firefox project (icons only) — also needs a prior build
npm run test:build       # build + test (use this to avoid testing a stale build)
npm run evidence         # Evidence specs — UI-feature screenshots for PRs (separate runner, not part of npm test)
```

Manifests generated by `scripts/write-manifest.mjs` post-build — edit the script, not the output.

## Workflow

- New cross-context feature: define types in `shared/messages.ts` first, then implement both sides.
- New state-owning logic: add a hook under `newtab/state/` consumed by `App.tsx` rather than growing `App.tsx` inline.
- New component: in `newtab/components/`, `<Name>Props` interface above it, callbacks as props.
- When two patterns conflict, pick one and surface the other for cleanup — never silently average.

## Gotchas & Constraints

Hard-won constraints. Violating these reintroduces shipped bugs.

- **`chrome.storage.sync` 8 KB per-item quota (`QUOTA_BYTES_PER_ITEM`).** Never store a growing collection under one sync key. Each `WorkspaceRecord` lives under its own key `workspace:<id>` (~630 B each) — NOT a single aggregate `workspaces` key — so the per-item limit applies per record, not to the whole set. This is what allows `MAX_WORKSPACES = 20` (`shared/constants.ts`). The old aggregate key overflowed 8 KB at ~14 workspaces. A one-time idempotent migration (`workspaces-per-key-migrated` marker in **local** storage; memoized promise per SW lifetime) splits the legacy key into per-id keys. Migration order in `service-worker.ts`: per-key first, THEN view/sort. `storage-buckets.ts` also keeps a defence-in-depth safety net: a sync write that hits the per-item quota permanently demotes that store instance to local storage and retries (`::demoted-to-local`). When adding any new synced collection, key it per-item the same way.
- **Icon origin-scrape and https→http downgrade hosts.** The extension holds only `https://*/*` host permission. Hosts whose `https://<host>/…` URLs `301` to `http://` (e.g. `lastepochtools.com`, `tbcarmory.com`) can't be followed — the redirected `http` fetch is CORS-blocked, and all 8 same-host origin probes fail identically, flooding the console. Fix (`icon-providers.ts` + `icon-image.ts`): `fetchAndValidateImage` reports a fetch *rejection* (network/blocked/cross-scheme redirect) distinctly from a clean miss (404/wrong-mime/too-small) via `onFetchRejected`. The origin-scrape loop bails after **2** rejections instead of firing all 8, and records the host in a per-session `originSkipHosts` set so the rest of the session skips its origin scrape entirely (falling through to S2 / Icon Horse / DDG). A clean 404 is NOT a rejection — hosts lacking `apple-touch-icon` but serving `favicon.ico` still resolve, so there's no quality regression. Don't "simplify" this back to firing all probes unconditionally.
- **Firefox MV3 CORS bypass uses XHR, not fetch().** On Firefox MV3, `declarativeNetRequest` session rules do NOT inject `Access-Control-Allow-Origin` onto `fetch()` responses (Chrome does). Firefox instead uses `XMLHttpRequest` on the background page with `host_permissions` to grant cross-origin access (`src/background/icons/platform.ts`). Branch via `isFirefox()` / `navigator.userAgent` → callers use `firefoxSafeFetch()` which wraps this logic. The manifest generator (`scripts/write-manifest.mjs`) reflects this: Chrome lists explicit favicon-service hosts (S2, DDG, Icon Horse) for `declarativeNetRequest` rules; Firefox uses only `['https://*/*']` since XHR honors the wildcard for host_permissions. See `.claude/architecture.md` "Dual-Target Builds" for depth.
- **Firefox background is a non-persistent event page — two guards keep messaging alive.** Firefox MV3 suspends the background event page after ~30s idle (`persistent: true` is an *error* in MV3), and (a) only wakes it for listeners registered *synchronously at document start* — `background.js` is a module script that evaluates too late, so `public/background-boot.js` (classic script, loaded first in `background.html`) registers the real `runtime.onMessage` listener and `service-worker.ts` publishes its handler into it via `__ffPublishBackgroundHandler`; (b) a pending onMessage response or in-flight XHR does NOT prevent suspension, so slow calls (sync's 10s XHR) go through `sendKeepingBackgroundAlive` (`newtab/lib/messaging.ts`), which pings the background every 1s while the request is pending. Removing either guard reintroduces user-visible "Receiving end does not exist" / "Promised response from onMessage listener went out of scope" toasts on Firefox. Regression: `tests/firefox-e2e/specs/sync-event-page.test.ts`. Depth: `.claude/architecture.md` "Firefox Event-Page Lifetime".
- **Icon pipeline silently swallows fetch rejections.** The icon pipeline returns `null` on network/CORS/permission blocks with no `console.error` → a permission regression looks like "it stopped trying." Add logs when debugging permission changes. See `.claude/architecture.md` "Icon Pipeline" for providers and the silent-failure antipattern.
